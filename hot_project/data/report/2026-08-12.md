### 项目定位与用途

Prime Agent 是一个开源的编码与研究代理，面向通用任务和长时间运行的工作流。它强调“自我改进”的 RLM（Recursive Language Model）式工作方式，把上下文、工具调用和子代理协作纳入持续运行的 Python 控制环境中，目标是让代理不仅能执行任务，还能在会话过程中沉淀可复用的工作模式与上下文。

### 解决的问题

它主要解决传统聊天窗口上下文易丢失、复杂任务难以持续推进的问题。README 说明，Prime Agent 通过持久化 REPL、可保留的 harness 状态和后台运行能力，让有用的工作上下文、记忆、技能与子代理规范不必依赖单次对话。这样更适合需要反复迭代、长周期跟进、并且需要证据驱动微调的工作。

### 使用场景

典型场景包括代码编写、研究辅助、后台长任务执行以及多子代理并行协作。目标用户可以是需要连续处理工程任务的开发者，或需要让代理在终端断开后继续运行的使用者。它也适合把重复工作沉淀成可导入的技能，供个人项目或团队工作流复用；但由于 README 摘录有限，更细的行业场景未能确认。

### 技术架构与特性

项目以 Python 持久化控制环境为核心，默认以 persistent IPython 作为内置模型工具，文件操作、shell 命令、工具使用和上下文管理都通过代码完成。其关键特性包括内建子代理 `rlm(...)`、可通过 `/refine` 对补充 harness 状态进行小步、基于证据的更新、支持回滚的快照，以及可导入的 Python skills。README 还提到守护进程式后台会话和代理间直接通信。

### 项目定位与用途

Cloudflare Computer 是一个运行在 Durable Object 里的虚拟文件系统与执行环境。它把工作区的权威状态保存在 SQLite 中，并通过 `workspace.runtime` 提供可插拔的执行面，支持把同一份工作区接到不同后端上运行。当前已提供容器、Isolate shell 和 Isolate JavaScript 三种后端，分别面向真实 Linux 容器、Shell 执行和 ECMAScript 模块执行。

### 解决的问题

这个项目主要解决工作区状态、文件系统与代码执行分散在不同环境中导致的一致性和切换成本问题。README 说明 Durable Object 持有唯一权威状态，部分后端直接通过 Workers RPC 访问，不需要第二份存储或额外同步；容器后端则把 SQLite 状态投影成真实 FUSE 挂载并回写。它适合在同一抽象下统一处理文件、命令和脚本执行，但信息显示仍处于预览阶段，设计和 API 都可能变化。

### 使用场景

从示例看，它可用于构建带有 `read`、`write`、`exec` 接口的工作区服务，也可作为容器内运行 `computerd` 并通过 HTTP 暴露文件与命令能力的底座。`examples/worker-shell` 和 `examples/worker-javascript` 分别展示了在 Dynamic Worker 中运行 Shell 或 JavaScript 的方式，`examples/think` 则说明它还能作为聊天代理的工作目录。目标用户更偏向实验、探索和原型开发者。

### 技术架构与特性

核心架构是 Durable Object + SQLite 作为权威状态层，外层通过 `workspace.runtime.exec(source, { backend })` 统一入口选择后端执行。容器后端使用 FUSE、`computerd` 和 capnweb RPC，同步工作区状态；Isolate shell 基于 just-bash，在 Dynamic Worker 中通过 Workers RPC 访问工作区；Isolate JavaScript 则支持结构化输入输出、相对导入、配置库、`node:fs/promises` 以及 `ws:git`、`ws:artifacts` 模块。后端按需懒连接，且可按稳定 ID 注册多个后端。
