### 项目定位与用途

这是 Unicity AOS 体系中的一个跨会话记忆组件，面向 Astrid OS agents 使用。它从工作区读取本地记忆状态，并通过 hook 将内容注入到系统提示词中，让代理在不同会话之间延续上下文。README 还将其描述为 OS 模型中的“persistent swap file”，用于承载会话外的长期上下文。

### 解决的问题

该项目主要解决代理在会话结束后容易遗忘历史信息的问题。由于 agent-written 内容可能持续增长，如果没有专门机制，记忆内容难以稳定保留并可能挤占上下文窗口。它通过读取 `.astrid/memory.md` 并在提示构建时自动注入，帮助代理记住上次发生的事情；文件缺失或为空时则不产生影响。

### 使用场景

适合需要跨会话保持状态的 AI 代理工作流，尤其是 Astrid OS 环境下的自动化助手、长期任务代理或多轮协作场景。典型目标用户是希望让 agent 记住项目进展、用户偏好、未完成事项或上一轮对话结论的开发者与系统集成者。信息不足以确认更多行业场景，只能确定其核心用于代理记忆延续。

### 技术架构与特性

项目通过 `prompt_builder.v1.hook.before_build` 介入每次提示组装流程，先从 VFS 读取 `.astrid/memory.md`，再包装成 `# Memory` 段落，并以 `appendSystemContext` 形式发布到按请求响应主题。它是只读注入侧，不负责写入；写入由 `astrid-capsule-fs` 的文件工具完成。内置 32KB 硬上限，超出部分会在 UTF-8 字符边界截断并标记 `[Memory truncated]`。

### 技术架构与特性

### 项目定位与用途

Open Interpreter 是一个面向低成本模型的轻量级编码代理，官方简介强调它适配 Deepseek、Kimi、Qwen 等开放模型。根据 README，它可在终端中启动会话，并提供类似 Codex 的交互体验，核心目标是把模型接入到可执行的代码代理工作流中。

### 解决的问题

该项目主要解决低成本模型在代码代理场景下“好用但不好调”的问题。README 提到它专注于模拟能让低成本模型发挥更好效果的 agent harness，并提供多种 harness 切换能力，说明它试图降低不同模型、不同协议与实际编码任务之间的适配成本，让模型更稳定地完成编码与执行相关操作。

### 使用场景

典型场景包括在本地终端直接使用编码代理进行开发、调试和代码辅助；也适用于希望接入 ACP 兼容编辑器或客户端的开发者。README 还提到它可作为 Codex SDK 的替代执行路径，适合已经围绕 Codex 构建工具链、但希望切换到底层二进制实现的人群。

### 技术架构与特性

从已提供信息看，项目以 Rust 重实现了 Kimi Code harness，并强调与 ACP、Codex 兼容。它支持通过 /harness 在 native、claude-code、kimi-code、qwen-code、deepseek-tui 等多种执行模式间切换，体现出较强的协议/运行时适配能力。近期提交还显示其持续修复发布快照、生成 schema、递归限制等问题，并新增 Kimi Code 视频读取能力。
