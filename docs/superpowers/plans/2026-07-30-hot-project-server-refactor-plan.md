# hot-project 服务端重构 · 实施计划

日期:2026-07-30
设计依据:[2026-07-30-hot-project-server-refactor-design.md](../specs/2026-07-30-hot-project-server-refactor-design.md)

## 贯穿全程的不变量

1. **旧 `hot_projects/` 全程不动,CI 继续跑。** 快照漏一天永久补不回(GitHub 不提供历史 star)。
   新包在旁边长,直到 P5 才切。
2. **spec 里所有「删除」指的是「不搬进新包」**,不是去旧代码里删。旧代码只作逻辑参考。
3. **每阶段留一个可重复运行的检查**,不是一次性验证脚本。下一阶段开工前上一阶段的检查必须绿。
4. **新包只允许单向依赖**:`顶层入口脚本 → agent → tools → provider`,横轴设施(store/tasks/llm)
   谁都能用,但它们不许 import 纵轴任何一层;`core/` 谁都能用且它 import 不了任何 I/O 模块。

## 阶段总览

| 阶段 | 交付 | 依赖 | 可并行 |
|---|---|---|---|
| P0 | 包骨架 + 配置切分 + 路径接管 + 依赖方向守卫 | — | — |
| P1 | 数据层(事务原语 / DB / 快照 / 收藏) | P0 | 与 P2 并行 |
| P2 | token 池(租约 + 三件事 + strikes) | P0 | 与 P1 并行 |
| P3 | 任务池(队列 + worker + 三种并发制度 + 派生) | P2 | — |
| P4 | 每日快照脚本(七步三屏障) | P1 P2 P3 | — |
| P5 | 入口脚本接线适配(api_server / cli / 其余 cron) | P1 P2 P3 | 与 P4 并行 |
| P6 | 影子并跑 → 切 CI → 数据搬到顶层 | P4 P5 | — |

P1 与 P2 无依赖可并行。P3 必须在 P2 之后(worker 要递租约)。P4 与 P5 都只依赖底座三件,
可并行 —— 但 P6 要两者都完成,因为切 CI 后旧包不再定时,web/cli 必须已经能在新底座上跑。

## P0 · 包骨架与配置切分

**交付**

- `hot_project/` 目录树按 spec「落地布局」建出,每个包一个 `__init__.py`,内容为空或只有文档串。
- `config.py` 单文件七节(旋钮 / 路径 / 环境变量 / 机密 / Web 安全 / LLM 目录 / 关键词表):
  `paths.py`(纯派生,无副作用)。
- 实测常量**不进 config**,写在各自模块顶部并带注明理由的注释:批大小 100、快照并发 4、
  锚点容差 2 天、覆盖率下限 0.5、搜索最小间隔 1.3s(进 token 池)。

**路径接管(不复制数据)**

`paths.py` 里读写分离,这是过渡期唯一需要理解的一处特殊性:

| 用途 | 指向 | 说明 |
|---|---|---|
| 读 DB / 快照 / 收藏 / 报告 | 旧包的真数据目录 | 与旧 CI 共读唯一权威,保证影子比对有意义 |
| 写 | 新包下的影子目录(gitignore) | 绝不覆盖真快照/真 DB |

两个常量各带一句注释说明「切 CI 时这两行合一,数据搬到仓库顶层」。`logs/` 新包自己写自己的,
不读旧的。`.pipeline_checkpoint.json` 不接管(新设计无 checkpoint)。

**验证(可重复运行)**

- 导入纯净性:在临时 HOME/CWD 下 `import hot_project.config`,断言**没有任何目录被创建**
  (旧代码 `config.py:236` 光 import 就 `os.makedirs`)。
- 影子写隔离:断言写路径不在真数据目录下 —— 这条防的是最贵的事故(覆盖真快照)。
- 依赖方向守卫:遍历新包全部模块的 import,断言无违反第 4 条不变量的边。这个检查要一直留着,
  它是防止耦合复发的唯一自动手段。
- `core/` 纯净性:断言 `core/` 下没有任何模块 import `store`/`provider`/`tasks`/
  `requests`/`os`(除 `os.path`)。

**完成判据**:三个检查绿;`policy.py` 里每个旋钮都有一句说明它调大调小会发生什么。

## P1 · 数据层

**交付**

- `infra/store/atomic.py`:唯一写原语 `transaction(path, *, create_if_missing=False)`。
  读盘失败一律抛异常(**绝不当空字典继续写**);调用方抛异常 = 放弃写入,盘上原样。
- `infra/store/universe.py`:DB 读写。字段归属表在此唯一声明并**在代码里强制**,不只是注释。
- `infra/store/snapshots.py`:新格式 `{"meta": {coverage, not_found}, "stars": {...}}`,
  兼容读旧扁平格式;读取只返回 `int | None`;容差顺延与自适应短窗口拆成两个函数。
- `infra/store/favorites.py`:收藏,走同一个事务原语。

**验证(可重复运行)**

- **对照脚本**:读真实 `hot_projects/data/Github_DB.json` 与 `data/snapshots/*.json.gz`,
  断言新读取层与旧读取层逐条相同(仓库数、每个仓库全部字段、快照每个键的 star 值)。
- **字段归属拦截**(在临时目录上写,不碰真数据):
  - 发现任务试图写 `gh_desc` 或顶层 `date` → 必须被拒
  - 周报刷新缺 `forks_count` 时 → `forks` 保持原值,不得写 0(曾真实发生过抹库事故)
  - 发现任务对已存在的仓库 → 只插新键,不合并
- **损坏不覆盖**:构造一个截断的 JSON,断言 `transaction` 抛异常且**原文件字节不变**。
- **拒绝写空快照**:coverage 低于下限时断言没有文件产生。

**完成判据**:对照脚本零差异;上述每条拦截都有一个会失败的反例证明它真的在拦。

## P2 · token 池

**交付**

- `provider/github/tokens/`:`async with pool.lease() as lease:`,退出自动归还,
  异常按类型自动标记。**调用方拿不到 token 索引**,租约直接给请求头。
- 池内对每个 token 管三件事,`lease()` 要求三者同时满足:占用(未被借走)、
  冷却(`available_at` 已过)、配速(距该 token 上次请求已满最小间隔)。
- 401 单一口径:strikes 冷却,连续 N 次才永久失效。
- 不搬进来:按索引取头的接口、跨事件循环防御、调用层 `with_token_rotation`、
  四处同步 `time.sleep` 配速。

**验证(可重复运行)**

- 租约自动归还:租约作用域内抛异常,断言 token 已归还且状态被正确标记(不泄漏、不永久烧)。
- 限流:标记后该 token 在 `available_at` 前不会被 `lease()` 选中;所有 token 冷却时
  `lease()` 阻塞而非报错。
- 401 strikes:一次瞬时 401 **不得**永久失效(这是旧代码两处 bug 的回归锁);连续 N 次才失效。
- 配速:同一 token 连续两次 `lease()` 间隔 ≥ 最小间隔;不同 token 各自独立不互相等待。
- **动态容量**:池里 3 个 token 时最多 3 个并发租约;标记 1 个失效后立刻变 2;
  新增 1 个后立刻变 4。这条锁死「不需要 `max_concurrency` 数字」这个设计决定。

**完成判据**:五条全绿,其中 401 与动态容量两条是本轮最关键的回归锁。

## P3 · 任务池

**交付**

- `infra/tasks/`:一条队列 + N 个协程 worker 持续领取。外部只有 `submit` 一个入口。
- 任务基类:`needs_github_token`、`concurrency: int | None`。三级解析 —— 调用方显式 →
  子类默认 → 基类默认。只有一个异步执行入口;任务**不持有池引用**,被动接收 worker 递来的租约。
- 三种并发制度按 spec 实现:token 绑定(`None` + 要 token,上限来自租约,**不建信号量**)、
  速率绑定(写死数字,建信号量)、无限制(`None` + 不要 token,上限是 worker 数)。
- 任务可派生任务:执行中可向同一队列提交;「全部完成」判定须正确处理派生。

**验证(可重复运行)**

- 三档并发各一条:
  - token 绑定任务的实际最大并发 = 可用 token 数,且改变 token 数后随之变化
  - 速率绑定任务的实际最大并发恒为声明值,**不随 token 数变化**
  - 无限制任务不占租约(可与 token 绑定任务同时跑满)
- 三级解析:调用方传参覆盖子类默认;不传时用子类默认;子类没声明时用基类默认。
- 派生完成判定:父任务派生 3 个子任务后立即返回,断言 `run_all` 等到全部 4 个都完成才返回
  (故意让子任务比父任务慢)。这是最容易写错的一处。
- 同类型两次并发提交带不同 `concurrency` 时的行为符合 spec 声明(后写覆盖,不叠加成两倍),
  并在代码里以 `ponytail:` 注明这是有意简化及其天花板。

**完成判据**:派生完成判定与三档并发全绿。

## P4 · 每日快照脚本

**交付**

顶层 `cron_daily_snapshot.py`,七步三屏障(见 spec)。本阶段新写的任务类型:

| 任务 | 并发制度 | 说明 |
|---|---|---|
| 关键词搜索页 | token 绑定 | |
| 星段探测 | token 绑定 | **按层并发**(BFS),不是深度优先串行 |
| 星段扫描页 | token 绑定 | 探测出段之后提交 |
| Trending 抓取 | 无限制 | 不吃 token、不受 Search 限流,可完全并行 |
| GraphQL 快照批 | 速率绑定 4 | 二级限流按 IP 计,加 token 不管用 |

淘汰做成 `core/` 里的纯函数:一份快照 + 一份 `not_found` 名单 → 该删的名字。

**验证**

- `--limit N` 调试模式对少量仓库跑通全链(发现→采集→写→淘汰),与旧脚本产出的快照**逐键比对**。
- 屏障顺序:构造「新仓库尚未入库」的情形,断言采集阶段不会漏掉它(屏障 1 生效)。
- 覆盖率闸门:模拟覆盖率不足,断言中止且**不落盘**。
- 淘汰纯函数:GitHub 判 null → 淘汰;star < MIN_STAR → 淘汰;
  **整批限流失败 → 不淘汰**(必须用 `meta.not_found` 区分「确认查不到」与「我们没问到」,
  这条错了会一次性删掉大批活仓库)。
- 幂等:当天已有快照时重复运行立即退出,不发任何请求。

**完成判据**:`--limit` 产出与旧脚本逐键一致;上述四条闸门各有反例证明生效。

## P5 · 入口脚本接线适配(与 P4 并行)

**只换接线,业务逻辑照搬。** 三个消费者从旧底座改到新底座:

| 消费者 | 要换的东西 |
|---|---|
| web server | `db.py` → `infra.store`;token 索引 → 租约;去掉自建的 ThreadPoolExecutor |
| cli | 同上 |
| 其余 cron(周报等) | 同上 + dispatcher → `infra.tasks` |

接口形状变了三处:租约取代 token 索引、事务取代四份手抄的锁读改写、单一异步执行入口取代
`execute`/`execute_async` 双入口。

**边界判据**:改动应集中在 import 与调用形式。**凡是发现要动业务判断,就说明该逻辑本就属于
下层**,应下沉到 `core/` 或工具层,而不是在入口脚本里改 —— 这是把 `tools/basic/core.py` 那种上帝模块
重新长出来的唯一入口,要在这一阶段守住。

**验证**

- web:起服务打通几个只读接口,断言返回与旧服务逐字段相同(读同一份真数据)。
- cli:同一条命令在新旧两边跑,输出比对。
- 依赖方向守卫(P0 建的)必须仍然绿 —— 适配过程最容易顺手加一条反向 import。

**完成判据**:三个消费者都能在新底座上跑通只读路径;写路径至少各有一条走通并被字段归属拦截验证过。

## P6 · 影子并跑 → 切 CI → 数据搬迁

1. **影子并跑**:新脚本每天在旧脚本之后跑一遍,读真数据、写影子目录。连续比对若干天,
   逐键一致 + 覆盖率不低于旧脚本。
   *操作摩擦*:`snapshots/` 只在 tmp 分支上,比对时工作区要能同时看到 tmp 的快照与当前代码。
2. **切 CI**:workflow 换成新脚本,旧脚本保留但不再定时(留作回滚)。
3. **数据搬到仓库顶层**:`git mv` 一次,`Github_DB.json` / `favorites.json` / `snapshots/` /
   `report/` 从 `hot_projects/` 下搬到顶层 `data/` 与 `report/`。同步改:新包 `paths.py`
   读写两行合一、CI workflow 里的路径、`.gitignore` 里那条关于 snapshots 追踪的说明。
   此后删掉 `hot_projects/` 不碰任何数据。
4. **回滚条件**:任何一天新脚本覆盖率低于旧脚本,或产出与影子期不一致,立刻切回。
   第 3 步之前回滚代价为零(旧脚本原地能跑);第 3 步之后回滚需同时还原路径,
   所以**搬迁必须等并跑稳定后单独做一次提交**,不与切 CI 混在一个提交里。

**并跑天数**取决于能否观察到边界情形(缺快照顺延、整批限流、GitHub 判 null),
至少覆盖一次限流较重的日子。

## 明确不在本计划内(后续轮)

- 增长口径的**实现**(口径本身已在 spec 定死):锚点相减 + 窗口内新建,其余未决;
  删掉 DB 差值与 DB 折算两条旧路;窗口只用锚点实际跨度。
  **前置条件**:快照攒够一个窗口。现在只有 07-29 一份,过早下手会让大批仓库变未决。
- 工具层的单点 `ToolSpec` 声明(设计已定死,实现在后续轮)。
- 采集/增长流水线其余部分、Agent 层、Web 层的**功能性**重写(P5 只做接线适配)。
- 两项真正的性能杠杆:星段拆分结果缓存到明天;量化 333 个关键词的边际发现量并砍一批。
- 存储格式迁移与 git 体积治理。
